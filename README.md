# hxyfront-62014 赛鸽训放 · 批次核验台

源提示词编号：9

面向赛鸽棚的训放记录工具，以**批次核验台**为核心：鸽主开立放飞批次、逐羽登记归巢报时，系统按统一规则即时核验，产出成绩排行、未归巢提醒、待复核队列与单羽档案。

## 核验规则

- **每羽唯一**：同一足环号在同一未结束批次中只能出现一次；重复提交返回 **409 冲突且不落库**（足环档案也不会写入）。批次结束后冻结，不再接受登记。
- **参数齐全才可计时**：放飞参数（地点、放飞时间、航距）与归巢报时须齐全。
  - 归巢早于放飞、缺航距、分速越界（400–1800 m/min）→ 只留待复核，**不进入排行**。
  - 双方报时都缺失 → 未归巢，进入未归巢提醒（仅未结束批次提醒）。
- **双方报时独立保留**：鸽主报时与传感器报时是两条原值，只可补录空通道、不可覆盖。双方差异超过 60 秒即挂「报时争议」，**保留双方原值**，须由提交人之外的另一人复核裁定（采信鸽主 / 采信传感器 / 作废）。
- **参数修订留档重算**：改动放飞参数时先把旧排行、旧待复核与旧未归巢统计冻结成快照留档，再按新值重算排行和提醒。
- **单一事实来源**：列表、统计、单羽档案全部由规则层纯函数从同一份存储即时推导，刷新后一致。

## 架构（规则 / 存储 / 页面分离）

```
src/
├── domain/            # 规则层：纯函数，不依赖 React 与存储
│   ├── types.ts       # 领域模型（批次、登记、复核、快照、核验结论）
│   └── rules.ts       # evaluateEntry / evaluateBatch / buildSnapshot /
│                      # buildPigeonProfile / buildOverview
├── storage/           # 存储层：localStorage 仓储 + 写入校验
│   ├── seed.ts        # 演示数据与 StoreError（带 HTTP 状态码：400/403/404/409）
│   ├── store.ts       # 冲突 409 不落库、参数修订先归档、报时只补不覆盖
│   └── react.ts       # useSyncExternalStore 绑定
└── ui/                # 页面层：批次核验台 / 鸽棚总览 / 单羽档案
    ├── Console.tsx
    ├── Overview.tsx
    ├── PigeonProfiles.tsx
    └── time.ts
```

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62014

## 校验

```bash
npm run typecheck      # TypeScript 严格类型检查
npm run verify:rules   # 规则层端到端核验（409 不落库、待复核、争议、
                       # 参数修订留档重算、刷新一致性等 12 项）
npm run build          # 生产构建
```

数据保存在浏览器 localStorage（键 `pigeon-batch-console:v1`），页面右上角可重置为演示数据。
