# hxyfront-62014 赛鸽训放 · 批次核验台

在原训放记录工具基础上升级为「批次核验台」：以训放批次为单位，对上笼登记、归巢报时、
第三方复核、成绩排行和未归巢提醒进行统一核验。

## 核验规则

- **一羽一批次一次**：同一未结束批次中每羽赛鸽只能上笼登记一次；重复上笼或重复归巢报时
  返回 **409 冲突且完全不落库**（页面会弹错误提示）。
- **参数/报时齐全才上榜**：放飞地点、放飞时间为必填，航距可暂缺（待补录）；鸽主与传感器
  两路归巢报时须齐全。只填一路会落库保留原值并转入复核队列，不进排行。
- **三类结构异常只留待复核**：归巢早于放飞、批次缺航距、分速超出 400–1700 m/min。
- **报时不一致保留双方原值**：两路报时差异超过 60 秒即标记不一致，鸽主报时与传感器报时
  原样保留，必须由**登记人/报时人之外的另一人**复核，采信认定时间或判无效。
- **改放飞参数自动重算并留档**：修改放飞时间/航距/地点/天气前，系统先快照每羽当时的
  状态、分速与待复核原因（「参数留档」页可查），随后排行与未归巢提醒按新值实时重算。
- 状态、分速、排行、统计**不入库**，全部由规则层从原始事实实时推导，因此列表、统计、
  单羽档案、历史成绩天然一致，刷新页面也不会漂移。

## 三层结构（规则 / 存储 / 页面分开实现）

```
src/
  domain/
    types.ts          # 领域类型：只描述原始事实（鸽主、批次、上笼记录、参数留档）
    rules.ts          # 纯函数规则：核验 evaluateEntry / 排行 ranking / 未归巢 / 统计
  storage/
    repository.ts     # localStorage 持久化 + 提交入口校验（201/400/404/409）
                      # 冲突与参数错误不调用 persist → 不落库；落库后广播刷新事件
  ui/
    useLoft.ts        # 唯一状态通道：落库后重新拉取整份快照
    DeskTab.tsx       # 批次核验台：参数、登记、报时、复核队列、排行、未归巢提醒
    LoftTab.tsx       # 鸽棚总览：建档、血统分布、跨批统计
    PigeonProfileTab.tsx  # 单羽档案：健康/配对编辑 + 跨批次参与历史与名次
    HistoryTab.tsx    # 按血统/距离分级/状态筛选的历史成绩
    ArchiveTab.tsx    # 放飞参数改动留档与旧结论快照
  lib/format.ts       # 统一时间/速度/距离格式化
  test/logic.test.ts  # 端到端规则校验（node + esbuild，38 条断言）
```

页面层不做任何业务判定，只读快照并调用 `domain/rules`；存储层不做速度/状态推导，只负责
事实的持久化与提交裁决。

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式），数据持久化使用 localStorage，无后端。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:62014
npm run build        # tsc 类型检查 + 生产构建
npm run test:logic   # 规则端到端校验（38 条断言）
```

首次打开会载入内置演示数据：一个已结束的 60km 批次和一个今日未结束的 80km 批次，覆盖
核验通过、报时不一致、报时不全、早于放飞、速度越界、未归巢等全部情形。页面右上角
「重置演示数据」可随时还原。
